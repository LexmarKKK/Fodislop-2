# Релиз обновления клиента

Самописного апдейтера больше нет: у каждого канала распространения свой механизм
доставки, а единая точка правды о версии — серверный гейт на входе
(`OutdatedClientPacket`). Клиент ничего не докачивает и не заменяет сам; всё, что
не входит в бинарник (текстуры, звук, банки), как и раньше, стримится с сервера
через рантайм-ассеты.

## Механизм: гейт версий

Сервер при `ClientHello` сверяет `ClientVersion` клиента с `MinimumClientVersion`
из `config.json` (`Session.CheckClientVersion`). Клиент ниже минимума получает
`OutdatedClientPacket` (имя версии, причина, **`ClientDownloadUrl`**) и разрыв:
клиент показывает сообщение и открывает ссылку на скачивание в браузере
(`StatusProcessor` + `ExternalUrlOpener`). Это единственный принудительный
механизм — он работает для всех каналов.

Поля `config.json` сервера:

| Поле | Роль |
|---|---|
| `MinimumClientVersion` | Минимальная версия, ниже которой вход закрыт |
| `ClientVersionName` | Человеческое имя версии (показывает `OutdatedClientPacket`) |
| `ClientDownloadUrl` | Куда вести игрока за новой сборкой |

## Доставка по каналам

- **Web**: хостинг отдаёт свежую сборку при каждой загрузке страницы. Рассинхрон
  возможен только у висящей открытой вкладки — гейт вернёт «обновите страницу».
- **Steam**: SteamPipe. Гейт сработает так же; в тексте сообщения можно
  ориентироваться на «дождитесь обновления в Steam».
- **Desktop (прямой)**: единый установщик поверх старой установки. Гейт ведёт на
  страницу скачивания (`ClientDownloadUrl`).

## Чек-лист релиза

Версии — связка «int ↔ имя»: `ClientVersion = N` ↔ `0.0.N`.

1. **Бамп версии**: `ProjectRuntimeContracts.Networking.ClientVersion` (+1) и
   `bundleVersion` в ProjectSettings (= 0.0.N). Число обязано совпадать с тем,
   что ожидает сервер.
2. **Сборка**: Kern/Build/Windows 64 → `Build/Windows/` (Mono, x64).
3. **Раскатка по каналам**: выложить сборку на хостинг (web), залить в Steam
   (SteamPipe), обновить страницу установщика (desktop).
4. **Поднять минимум**: в `config.json` сервера
   `"MinimumClientVersion": N, "ClientVersionName": "0.0.N"` (и при смене адреса —
   `ClientDownloadUrl`). Перезапустить сервер. Старые клиенты при следующем входе
   получат окно «требуется версия N» и ссылку на скачивание.
   - Мягкая раскатка: не поднимать `MinimumClientVersion` — старые клиенты
     продолжают играть, пока минимум не поднят.

## Почему апдейтер снесли

Конвейер «подписанный манифест → дифф → staging → рестарт-скрипт» копировал
модель Steam ради мульти-гигабайтных игр: клиент небольшой, обновляется редко, а
контент и так докачивается с сервера на лету. Дублировать доставку ради бинарника
нецелесообразно: web обновляется перезагрузкой, Steam — своим апдейтером, desktop —
переустановкой одним установщиком. Гейт версий при этом сохраняет главное свойство —
старая сборка не может играть с новой.

## Ограничения

- **Player Settings → Other Settings → Allow downloads over HTTP = Always allowed**
  (`insecureHttpOption: 2`) — всё ещё нужно для бейджа онлайна и рантайм-ассетов
  по http:// (до переезда сервера на https).
- Desktop-обновление требует действия игрока (запустить установщик) — осознанный
  обмен за простоту.
