Исправление повторного входа через Dummy

После отказа TCP сохранялись _shouldAutoReconnect и _restartWorldOnConnect. Повторный startup мог принять активную попытку подключения за ожидание повторного подключения и поставить в очередь ещё один переход MainGame; поздний сброс состояния после ожидания сцены создавал зависимость от самой готовности сцены. Connect теперь обозначает подключение из уже запущенного GameStartupPipeline; автоматический retry вызывает отдельный ConnectTransport. Новая попытка завершает ожидание retry, а настоящий disconnect снова включает его. Поздняя очистка состояния удалена; MarkWorldReady сохраняет проверку IsConnected и завершает состояние startup.

Production PlayMode-регрессия RetryPending_DummyWorldEntryClearsRetryAndKeepsOneGameScope воспроизвела прежний сбой без исправления (/tmp/kern-dummy-startup-before.xml), затем прошла с исправлением (/tmp/kern-dummy-startup-after.xml): действующий DummyConnection, WorldLoaded, MainGame ready, один GameLifetimeScope. Отдельная негативная проверка DummyDisconnectDuringHandshake_DoesNotEnterWorld прошла (/tmp/kern-dummy-startup-disconnected.xml): при обрыве handshake вход отклоняется, игровая сцена выгружается, остаётся MainMenu. Таймауты не изменены. Проверки выполнены headless в полной копии проекта с отдельными company/product для изоляции конфигурации. Исходный Unity Editor не управлялся. Архитектурный source linter прошёл; лог /tmp/kern-dummy-startup-linter.log.
