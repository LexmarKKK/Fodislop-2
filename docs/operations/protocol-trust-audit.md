# Разбор доверия к клиенту

Что клиент сообщает серверу и где он сообщает **результат** вместо
**намерения**. Составлено по определениям пакетов в
`darkar25.kern.networking` и по местам отправки в `Assets/Scripts`.

**Границы разбора.** Серверный код не читался — доступа нет. Ниже сказано,
какие данные сервер получает и какие проверки на них возможны; проверяет ли он
их сегодня, отсюда не видно. Каждый пункт — вопрос к серверной стороне, а не
утверждение о её дефекте.

**Исходная посылка.** Клиент открыт, значит протокол известен целиком и
обфускация ничего не стоит. Единственная асимметрия, которая остаётся:
читатель видит себя, сервер видит всех. Всё полезное строится на ней.

---

## 1. Где клиент сообщает результат вместо намерения

### 1.1. Своя позиция в каждом действии

```csharp
// NetworkService.cs:136-141
Vector2Int pos = _cachedPlayerController.Position;
Send(new ActionClientPacket((ushort)pos.x, (ushort)pos.y, action));
```

`ActionClientPacket(X, Y, Payload)` несёт координаты, взятые из клиентского
состояния игрока. Это самое крупное место: под ним ходят **все** действия —
копание, постройка, гео, лечение, переключение режимов.

Развилка простая и третьего не дано:

- Если сервер использует `X`/`Y` как позицию игрока — это телепорт и действие
  на любом расстоянии одной строкой в самописном клиенте.
- Если сервер держит свою позицию и `X`/`Y` игнорирует — поле бесполезно и
  является чистой поверхностью атаки.

**Что с этим делать.** Не «использовать», а «сверять»: пришедшие координаты
сравнивать с серверной позицией и при расхождении действие отклонять, а
расхождение считать. Само поле тогда превращается из данных в утверждение
клиента о себе, и каждое ложное утверждение — сигнал.

### 1.2. Движение задано целью, а не направлением

```csharp
MovePacket(ushort X, ushort Y)   // абсолютные координаты клетки
```

Намерение здесь — «шагнуть вправо», результат — «я в клетке (312, 480)».
Передана вторая форма. Сервер обязан сам проверять смежность с текущей
позицией, проходимость, откат и время с прошлого шага; если он этого не делает,
`MovePacket` — это телепорт по определению.

`RotatePacket(Direction)` устроен правильно: направление, а не итог.

### 1.3. Значения полей ввода приходят от клиента

```csharp
// ServerWindowPresenter.cs:154
_networkService.Send(new ElementClickPacket(windowTag, elementIndex, inputValues));
```

`ElementClickPacket(WindowTag, ElementIndex, Context)` несёт список пар
«имя-значение» из полей окна. Окно при этом **прислал сам сервер**
(`OpenWindowPacket` с полным составом компонентов), то есть серверу известно:

- какие окна открыты у этого игрока прямо сейчас;
- какие в них есть элементы и какие из них вообще кликабельны;
- какие поля ввода есть, какого они типа и какие значения допустимы —
  `SliderPacket` знает свои границы, `IntDropdownPacket` и
  `StringDropdownPacket` — свой список вариантов.

Значит проверка бесплатна и полна: клик по окну, которое игроку не открывали;
индекс элемента вне присланного состава; значение слайдера вне его же границ;
вариант выпадающего списка, которого в списке не было. Всё это — не ошибки
честного клиента, а прямые признаки самописного.

Это самое ценное место в протоколе: через окна проходит экономика — магазин,
крафт, склад, улучшения.

### 1.4. Приветствие целиком клиентское

```csharp
ClientHelloPacket(int ClientVersion, string OS, int OSVersion,
                  string HardwareFingerprint, string AuthToken)
```

Актуальное состояние клиента (`ConnectionManager.CompleteConnectionAsync`):

- `ClientVersion` — константа `ClientProtocolVersion.ClientVersion`
  (сейчас `1`); сервер гейтит по ней актуальность релиза
  (`OutdatedClientPacket (0)`). Это гейт версии, а не защита: самописный клиент
  назовётся любой версией.
- `OS` — зашитые строки: `"Windows"`/`"macOS"` по `Application.platform`,
  прочие платформы отдаются как `RuntimePlatform.ToString()`.
- `OSVersion` — только `Environment.OSVersion.Version.Major` (Windows 10/11
  неразличимы).
- `HardwareFingerprint` — `SystemInfo.deviceUniqueIdentifier`.
- `AuthToken` — токен из `AuthTokenManager` (PlayerPrefs `AuthToken6`) либо
  пустой при первом входе (сервер выдаёт новый через `AuthTokenPacket (45)`).

Отсюда следует ровно одно: **доверять в протоколе можно только `AuthToken`**.
`ClientVersion` — исключительно гейт актуальности клиента, а `OS`, `OSVersion`
и `HardwareFingerprint` — метаданные наступаемости/диагностики: сервер не
должен ветвиться на них нигде (ни авторизация, ни геймплей, ни лимиты).

### 1.5. Программа робота

`SaveProgramPacket(ProgramId, SaveAndRun, Program, Breakpoints)` — произвольный
список операций и массив точек останова. Нужны серверные пределы: длина
программы, число точек останова, допустимость каждой операции, частота
сохранений. Без них это самый дешёвый способ занять сервер работой.

## 2. Инварианты, которые сервер может проверять уже сейчас

Данные для них в протоколе есть, дополнительных полей не требуется.

**Метка времени конверта.** `ClientPacket(uint Timestamp, IRootClientPacket)`.
Наш клиент кладёт туда `(uint)DateTimeOffset.UtcNow.Ticks` — обрезанные тики,
величина без смысла. Сейчас поле декоративное, а могло бы быть счётчиком:
монотонность в пределах соединения, попадание в окно серверного времени,
отсутствие повторов. Живой клиент это выполняет само собой, самописный —
почти никогда, потому что автор воспроизводит смысл, а не последовательность.

**Порядок.** Действие раньше, чем сервер прислал то, что его разрешает: клик
по окну до `OpenWindowPacket`, действие до инициализации мира, использование
предмета без предшествующего `SelectItemPacket`. Честный клиент такого порядка
не порождает.

**Бюджеты на тип действия.** Не «запрещено», а «не чаще возможного»: действий
в секунду, кликов по окну, сохранений программы, передач между аккаунтами в
час. Ограничение скорости превращает найденную дыру из мгновенной в медленную,
а медленную успевают заметить.

## 3. Ловушки

Дешевле всего ловится тот, кто собрал клиент по исходникам и воспроизвёл
протокол, но не знает, что честный клиент делает не всё, что может.

**Элемент, которого нет на экране.** Сервер присылает окно, в котором один
компонент не отображается честным клиентом — скрытый, нулевого размера,
за пределами списка. Клик по нему невозможен глазами и тривиален по протоколу.

**Клетка или предмет, который клиент не показывает.** Тип, который отрисовщик
отбрасывает. Тот, кто читает поток напрямую, о нём узнаёт и пытается
использовать.

**Поле, которое честный клиент игнорирует.** Добавленное в серверный пакет
значение, которое никто не читает. Самописные клиенты часто отражают такие
поля обратно или ведут себя иначе, когда оно меняется.

Ловушек нужно несколько, они должны выглядеть как обычные данные, и **ни одна
не должна приводить к немедленному отключению** — иначе она превращается в
отладчик: за час двоичным поиском выясняется, что именно палит.

## 4. Статистика вместо правил

Человек шумит, программа — нет. Что имеет смысл мерить именно здесь:

- разброс интервалов между действиями копания: у человека десятки
  миллисекунд, у бота близок к нулю;
- время реакции на появление объекта: у человека 180–300 мс, никогда 20;
- форма пути между точками: у человека кривая, у бота оптимальная;
- доля действий, попадающих ровно в границу дозволенного (максимальная
  дальность, минимальный интервал): человек в неё почти не попадает, бот живёт
  на ней.

Ловить надо распределение, а не событие. Один идеальный клик — совпадение,
тысяча подряд — нет. Подделать это дорого: нужно не протокол переписать, а
правдоподобно сымитировать человека.

---

## 5. Чего не делать

Обфускация, контрольная сумма клиента, проверки внутри клиента. При открытом
исходнике это неделя работы и вечер на обход. Привязка к аппаратуре тем же
свойством: клиент подписывает своими же данными, и самописный подставит любые.
Античит уровня ядра — отдельный продукт, враждебный игроку и несоразмерный
игре про шахты.

---

## 6. Порядок работ

1. Сверять `ActionClientPacket.X/Y` с серверной позицией и считать расхождения.
   Одно место, под ним все действия.
2. Проверять `ElementClickPacket` по составу окна, который сервер сам и
   прислал. Здесь экономика.
3. Проверять `MovePacket` на смежность и время от прошлого шага.
4. Бюджеты по типам действий.
5. Счётчик в метке времени конверта; на клиенте это одна строка в
   `NetworkService.Send`.
6. Ловушки — две-три, с накоплением, без немедленной реакции.
7. Статистика — последней, когда предыдущее уже отсекает грубые случаи.

Пункты 1–4 не требуют изменений в клиенте вообще. Пункт 5 требует одной
строки. Пункт 6 — только серверной стороны и содержимого окон.
