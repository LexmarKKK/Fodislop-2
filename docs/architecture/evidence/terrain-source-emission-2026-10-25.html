Три метода свечения в debug-режиме

TL-OWN, TL-API, TL-LIFE, TL-REV, TL-STAGE, TL-DATA, TL-PERF, TL-VERIFY, TL-CHANGE. Запрос: сохранить исходную эмиссию, общий порог яркости и адаптивный метод для визуального сравнения. Переключатель расположен в F1 → «Отладка террейна» → «Метод свечения · эксперимент». Исходный метод включён при старте каждой play-сессии. Эксперименты не сохраняются в пользовательский конфиг; вне Editor/Development запрос экспериментального метода отклоняется.

HDR и альфа

RGB исходного sRGB atlas декодируется GPU один раз. CPU анализирует linear float4. Кэш хранит premultiplied RGB-коэффициенты и mask×sourceAlpha; заголовок содержит общий transport gain = ΣY(original×alpha)/ΣY(masked), Y=0.2126R+0.7152G+0.0722B. Gain применяется только к RGB transport. Нет clamp/saturate на radiance; saturate используется только для UV/масок. В transport остаётся существующий GlowScale=12.

В новых методах видимая поверхность получает отдельный source emission с SurfaceEmissionStrength=1, после incoming light/AO. Transport gain и GlowScale к нему не применяются. Это устраняет прежний белый пересвет от ошибочного множителя 12. Adaptive surface читает point alpha того же исходного texel и снимает premultiplication кэша до обычного SrcAlpha blending: частичная прозрачность применяется один раз. Проверка alpha=128/255 требует G=2×128/255 в обоих новых методах.

Осмотренные изображения

Функциональные методы и scoped production GPU проверки завершены. Ни один автоматический метод не гарантирует семантическое выделение «именно кристалла» на произвольной новой картинке.
