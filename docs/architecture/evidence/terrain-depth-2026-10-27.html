TL-OWN / TL-API change contract

TerrainVolumeTopology derives exposed contour edges from the accepted cell/type buffers during commit. TerrainVolumeMesh uploads actual side quads, each with lower and upper edge vertices. Its submeshes are stationary ground, side geometry and raised foreground. TerrainDepth.hlsl projects height from the active camera using eye height H=32 cells, physical height h=DepthPixels/32, and a half-cell displacement cap. The face and wall top use the same forward vertex projection; homogeneous W preserves perspective interpolation of side UVs. No fragment-image copy or inverse silhouette sweep remains.

Square/wavy blocks use exposed polygon sides. Round blocks use cached contours on the real 32-pixel occupancy lattice, including the production disk, connected quadrants and corner-exclusion rule. Collinear pixel edges merge without changing contour coverage. Camera-facing walls are selected by outward normals. UV tangent follows the edge; UV depth advances into the block material. Light/AO sample the original surface; no new light transport or source is introduced.

Physics, navigation, cell packing, lighting field meshes and solver dispatches are unchanged. TerrainSettings.DepthPixels and DepthDarkening retain ranges 0–16 and 0–1, defaults 16 and .35. Their advanced-settings apply path updates presentation uniforms without a terrain/lighting reset. Schema 45 migrates to 46 through the existing defaults-overlay/backup pipeline; explicit saved values including zero are preserved, and incomplete current-schema files still fail validation.

Dependency scans: full output; both have zero matches. Changed-line review found no new Terrain→Lighting implementation dependency, reverse dependency, aliases, reflection, service lookups or cross-domain event path. Existing unrelated architecture debt is not waived.

TL-PERF cost and diagnostics

Let N be visible presentation cells, M committed backing-window cells, E committed exposed/merged side edges. Before the feature: 8N vertices, 12N indices, 112N payload bytes and one screen draw. Current: 8N+4E vertices, 12N+6E indices, 176N+88E payload bytes, three draws. This includes packed POSITION endpoint data; it excludes Unity bookkeeping and retained managed-list capacity. Square cells contribute at most four sides; round cells have at most 128 unmerged pixel sides and fewer merged runs. Physical field mesh storage is unchanged. No new texture, compute buffer or light dispatch is allocated.

On commit, exact shape-input comparison is O(M+halo+256). A changed topology additionally visits the node lattice when needed and the cells/edges. Sixteen round-mask contour tables are built once from 32×32 occupancy and merge straight runs. Scratch storage: one Vector2 per node, one byte per cell+halo, 256 uint shape words, plus retained edge/list capacity. Mesh regeneration is O(N+E), and writes GPU buffers only on topology/visible-size changes. Stable camera travel does no CPU edge rebuilding and no mesh upload. All E side quads are submitted, but out-of-view vertices exit before cell-buffer reads. In-view side vertices add one existing cell decode per vertex; the native decoder check still reports 19 foreground and 27 background reads. Wall fragments no longer perform seventeen silhouette sweeps.

FrameEventLog records topology version, cells/edges, CPU build milliseconds, mesh vertices, wall quads and payload bytes. SubmittedDepthCarrierQuads is retained as a compatibility diagnostic name and now reports actual submitted side quads, not visible fragments. GPU-facing work can grow with visible wall area. No performance improvement is claimed.
