Bloom extraction/reconstruction — TL-CHANGE, 2026-10-27

Change contract / ownership

User reports smeared bloom and requests algorithm review. Owner: rendering post-processing, WorldBloom.compute. Producer: real pre-tonemap HDR scene plus published world glow; consumer: existing scene-linear additive pass. No lighting transport or geometry ownership change.

Defect: previous quarter-resolution prefilter applied a nonlinear threshold to four bilinear averages, erasing isolated above-threshold sources. With hard threshold 1 and one white source pixel at radiance 2, the old averaged value 0.5 contributes zero; independent expected integrated quarter-pixel contribution is (2−1)/16 = 0.0625. The previous MainGame assertion explicitly expected the former order.

Extraction now tests each source pixel before averaging all sixteen values. Scene radiance uses integer mip-zero Load; eligibility uses point-sampled glow to prevent adjacent non-emitter leakage. Padded source positions outside the viewport contribute black, without duplicating edge pixels.

The former four-offset diagonal filter used the same large artistic radius during 2× reduction and reconstruction. Reduction now uses a fixed normalized 3×3 tent; reconstruction uses the same normalized kernel with the authored radius. The independent center/axis/diagonal impulse weights are 1/4, 1/8 and 1/16. Existing scatter, intensity, threshold, knee and radius defaults are unchanged. Pyramid energy normalization remains valid and unchanged.
