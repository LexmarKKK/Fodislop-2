Mining / heal / hurt emission — TL-CHANGE, 2026-10-27

Contract / ownership / compatibility

Requested behavior: mining sparks, healing and damage effects illuminate the world. Game visual-effect owners publish sources through the existing LightingEngine.SetDynamicLight/RemoveDynamicLight API. No source-color palette, additional animation, static-glow sprite registration, geometry revision, transport shader or tone transform is introduced.

AssetPipeline owns SpriteEmissionFrame: integrated linear RGB over world-cell area and source centroid in effect-local cell units. AnimatedSpriteData now includes this per-frame array; its single project producer is updated. This is an in-memory source API change, not a packet or persistent-client-config format change. Bz declares ComputeEmission in AnimationFrameLayouts.json; unrelated assets do not compute or retain emission pixels.

Independent numeric evidence

Opaque red plus transparent cyan over four cells integrates to RGB (2,0,0), proving coverage and no HDR clamp. Encoded gray 128 with alpha 128 integrates to approximately 0.1083535 per channel over one cell: decode before premultiplication. A left texel of a two-cell-wide frame has centroid X −0.5 cells. Negative XY scale (−2,3) multiplies RGB by area 6; it does not invert energy.

Independent standard-library PNG oracle on actual source atlases: Hurt 15 frames, channel maxima (0.5209360, 0.1109745, 0.1109745); Heal 5 frames, maxima (0.1931410, 0.4284371, 0.1629876); Bz 15 frames, maxima (0.4323326, 0.3762916, 0.2509271). Values precede the normal world gain. Sources derive their colors from art rather than hardcoded red/green/orange.

TL-PERF

Steady state adds one managed source holder and one existing dynamic-source entry per live effect. No per-frame texture scan, GPU readback or new visual mesh. Each active owner submits a constant amount of math and an O(log L) manager lookup. An unchanged source is deduplicated; changing animation frame, area or world position uses existing dynamic invalidation. No solve-rate cap or frame skipping.

Bz cache metadata payload is 15×24 = 360 bytes. SpriteAnimationLibrary stores 314×24 = 7536 bytes for indexed frame metadata (unused entries zero), plus temporary source pixels for the two relevant textures during import. Bz scans 32×960 pixels once and can require the existing Apply call to release CPU pixels on the texture-first route; unrelated textures avoid that path. Heal/Hurt integration visits their authored source rectangles once per referenced mesh.

GPU work increases with visible active effect sources, within the unchanged dynamic-source capacity. Each uploaded source uses the existing 32-byte GPU descriptor. Existing batching may combine dispatches: additional polar work is bounded by the existing E×rayWidth×rayHeight for each newly invalidated source, and receiver work by its clipped rect area. Existing ray/horizon/tile caches can grow to the established capacity. Track DynamicLightCount, UploadedDynamicLightCount, DroppedDynamicLightCount, LightingDynamicPolarDispatchCount, dynamic receiver counters and DDA telemetry; static-frame and changing-frame costs must be measured separately. No production GPU measurements or FPS claim.
